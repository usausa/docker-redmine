# 🐳 docker-redmine

Redmine 7 を Docker / docker compose で構築・運用するための構成一式です。

---

## 🎯 コンセプト

- 📦 **公式イメージを土台にする**: `redmine:7.0.2-bookworm` と `postgres:17-bookworm` を docker compose で動かします
- 🧱 **プラグインはビルド時に焼き込む**: `plugins.tsv` と `themes.tsv` に「名前・取得元・固定したリビジョン」を書いておくと、`docker compose build` でイメージに入ります
- ⚙️ **初期設定もコマンド1つで入れる**: ステータス・トラッカー・管理画面の設定・表示のカスタマイズなどを、初回の起動のあとにスクリプトで登録します
- 🚫 **Redmine 本体とプラグインのソースには手を入れない**: 変えるのは、設定と、view_customize で足す CSS / JavaScript だけです
- 🔐 **環境ごとの値は `.env` だけに書く**: パスワードやメールアドレスはリポジトリに置きません

| パス | 役割 |

| `setup/initial_setup.rb` | 初期設定のスクリプト |
| `setup/custom_fields.yml` | 初期設定で作るカスタムフィールド |

## 🚀 導入手順

### 0️⃣ 前提

- 🐧 Linux のサーバーに Docker Engine と Docker Compose v2 以降（`docker compose` コマンド）があること
- 🧰 リポジトリの取得に `git` を使います（無い場合は、ファイル一式をサーバーへコピーしてもかまいません）
- 🌐 ビルドのときに、GitHub・rubygems.org・Docker Hub・deb.debian.org へ接続できること（イメージは Debian ベースで、ビルドの中で Debian のパッケージを入れるため、サーバーの OS に関係なく deb.debian.org が必要です）
- 🔌 8080 番ポートが空いていること

### 1️⃣ リポジトリを取得する

```bash
git clone https://github.com/usausa/docker-redmine.git
cd docker-redmine
```

### 2️⃣ `.env` を作る ✏️

```bash
cp .env.example .env
```

`.env` に次の値を入れます。導入する人が値を入れるのは、このファイルだけです。

| 変数 | 入れる値 |
|---|---|
| `DB_PASSWORD` | PostgreSQL のパスワード。`openssl rand -base64 24` で作る |
| `SECRET_KEY_BASE` | セッションの署名鍵。`openssl rand -hex 64` で作る。**一度決めたら変えない**（変えると全員のログインが切れる） |
| `SETUP_HOST_NAME` | 利用者が開く URL のホスト名とポート（例: `redmine.example.com:8080`）。通知メールのリンクに使う |
| `SETUP_PROTOCOL` | `http` または `https` |
| `SETUP_MAIL_FROM` | 通知メールの送信元アドレス |
| `SETUP_ADMIN_EMAIL` | 管理者（`admin`）のメールアドレス |
| `SMTP_ADDRESS` | SMTP サーバー。**空のあいだはメールを送らない** |
| `SMTP_PORT` | SMTP のポート（既定 `587`。STARTTLS を使う） |
| `SMTP_DOMAIN` | SMTP の HELO に使うドメイン（空でもよい） |
| `SMTP_USER` / `SMTP_PASSWORD` | SMTP の認証情報。認証が要らないサーバーなら `SMTP_USER` を空にする |
| `REDMINE_VERSION` | `7.0.2` のまま（版を上げるときに書き換える） |

> 💡 値に `$`・`#`・空白を含めるときは、値全体を `'...'` で囲みます。

### 3️⃣ Checklists の zip を置く ✏️

RedmineUP の配布ページ（<https://www.redmineup.com/pages/plugins/checklists>）から **Light 版（無償）** を入手し、`vendor/` に置きます。

```bash
ls vendor/redmine_checklists-4_1_1-light.zip
```

> 🔴 Checklists が無いと、チェックリストの完了数から進捗率を計算する運用ができません。zip はライセンス物のため Git 管理外です（[vendor/README.md](vendor/README.md)）。

### 4️⃣ 業務に固有の選択肢を用意する ✏️（必要なとき）

カスタムフィールド「検出時機能機能名」の選択肢のように、業務に固有のものは `setup/custom_fields.local.yml`（Git 管理外）に書きます。

```bash
cp setup/custom_fields.local.yml.example setup/custom_fields.local.yml
```

> 📌 初期設定はカスタムフィールドがまだ無いときだけ作ります。初期設定の前に用意してください。後から足す場合は、管理 > カスタムフィールド で選択肢を追加します。

### 5️⃣ ビルドして起動する

```bash
mkdir -p data
docker compose build
docker compose up -d
docker compose ps
```

`redmine` が `healthy` になれば起動完了です（初回は DB の作成があるため1〜3分かかります）。

### 6️⃣ 初期設定を入れる

```bash
docker compose exec -u redmine redmine bin/rails runner setup/initial_setup.rb
```

最後に `✅ 初期設定が終わった` と出れば完了です。`⚠️ 確認が必要なこと` が出たら、`.env` の値を見直してからもう一度実行します（何度実行しても同じ結果になります）。

> 📌 実行の最初に出る `DEPRECATION WARNING` は、プラグインが出す将来の Rails 向けの警告です。無視してかまいません。

### 7️⃣ ログインする

ブラウザで `http://<サーバーのホスト名>:8080/` を開き、Redmine の初期アカウント **`admin` / `admin`** でログインします。初回にパスワードの変更を求められます。

### 8️⃣ 環境ごとの設定を管理画面で入れる ✏️

初期設定では入れない、環境ごとに違うものです。

- [ ] **利用者のアカウント**を作る（管理 > ユーザー）
- [ ] **プロジェクト**を作り、使うモジュールを選ぶ（新しいプロジェクトの既定のモジュールは初期設定で選んである）。利用者をメンバーに入れ、ロールを割り当てる
- [ ] 各プロジェクトの設定で **`Assign Notice URL`** に通知先の Webhook の URL を入れる（担当者の変更を Teams などに通知したいプロジェクトだけ）
- [ ] 必要なら**保存済みクエリ**を足し、プロジェクトの既定のクエリを決める（全員向けの7件は初期設定で作ってある。既定のクエリは、チケット一覧とチケットパネルを開いたときの初期の表示になる）
- [ ] 必要なら、管理 > 設定 の **ウェルカムメッセージ** を書く
- [ ] 必要なら、**ロールの権限**と**ワークフロー**を運用に合わせて調整する
- [ ] **バックアップ**を定期実行にする（[💾 バックアップ](#backup)）

### 9️⃣ 実際に使って確かめる ✅

使い始める前に、実際の操作で次を確かめます。

- [ ] **チケットの作成**: カスタムフィールドとテンプレートが使え、選択欄は文字を打って絞り込める
- [ ] **チェックリスト**: 項目にチェックを入れると進捗率が変わる。未完了の項目があると終了にできない
- [ ] **チケット一覧**: ステータスごとの色分け、期日超過、60日以上更新の無い行に色が付く
- [ ] **チケットパネル**: ドラッグでステータスが変わる
- [ ] **添付ファイル**: 画像のサムネイルを押すと拡大表示され、PDF はページの中で見られる
- [ ] **通知メール**: 管理 > 設定 > メール通知 の「テストメールを送信」と、チケットを更新したときの通知が届く
- [ ] **担当者の変更の通知**: `Assign Notice URL` を入れたプロジェクトで担当者を変えると、Teams などに通知が届く
- [ ] **出力**: チケット一覧の Excel（xlsx）・CSV・PDF が出せる（PDF では名前の絵文字が化ける）
- [ ] **ガントチャート**: 表示と、PDF・PNG の出力（PNG の日本語が抜けない）
- [ ] **バーンダウン**: チケットに対象バージョンを設定すると、バージョンの画面に出る
- [ ] **Wiki**: コメント欄と、Mermaid の図
- [ ] **保存済みクエリ**: それぞれ期待どおりのチケットが出る
- [ ] **個人設定**: テーマの切り替えと、アバター画像
- [ ] **バナー**: 管理画面で出したお知らせが全画面の上部に出る
- [ ] **バックアップとリストア**: バックアップから一度戻してみる（戻せないバックアップは意味がない）

## 🛠️ このパッケージが書き換える箇所の一覧

Redmine の公式イメージと既定の設定から、このパッケージが変える箇所です。

### 🐳 イメージ（`Dockerfile`）

- 🧩 `plugins.tsv`・`themes.tsv`・`vendor/*.zip`・`patches/` を読んで、プラグインとテーマをイメージに入れる
- 🔨 ビルド用のパッケージ（`patch`、`unzip`、`build-essential`、`libpq-dev`、`libmagickwand-dev`）を足し、プラグインの gem をビルド時に入れる
- 🔤 日本語フォント `fonts-ipaexfont-gothic` を足す（ガントの PNG 出力で日本語を描くため）

### 📄 サービス（`compose.yaml`）

| 項目 | 値 |
|---|---|
| DB | PostgreSQL 17。DB と Redmine の両方にヘルスチェックがあり、Redmine は DB が使えるようになってから起動する |
| イメージの名前 | `local/redmine:<版>`。前の版のイメージが残るので、`.env` を戻せば前の版に戻せる |
| `SECRET_KEY_BASE` | `.env` の値に固定する（コンテナを作り直してもログインが切れない） |
| `REDMINE_PLUGINS_MIGRATE` | `1`（起動時にプラグインのマイグレーションを実行する） |
| タイムゾーン | `Asia/Tokyo` |
| データ | DB は `data/postgres`、添付ファイルは `data/files` |
| 公開ポート | `8080` |

### ⚙️ Redmine の設定ファイル（`config/configuration.yml`）

| 項目 | 値 | Redmine の既定値 |
|---|---|---|
| `email_delivery` | `SMTP_ADDRESS` が空ならメールを送らない。値があれば `.env` の SMTP で送る | 未設定（送らない） |
| `minimagick_font_path` | IPAex ゴシック（ガントの PNG で日本語を描く） | 未設定（日本語が抜ける） |
| `sudo_mode` | `false`（重要な操作の前にパスワードを再入力させない） | `true` |

## 🔄 運用

### 🧩 プラグインを足す・更新する・外す

`plugins.tsv` に1行足す（版を上げるなら3列目の `ref` を書き換える、外すなら行を消す）だけです。`ref` には必ずタグかコミットを書きます（`master` を書くと同じものを作り直せなくなります）。

```bash
docker compose up -d --build
```

gem はビルドのときに解決されるので、ビルドが通れば起動も成功します。失敗はビルドの段階で起きるため、動いているコンテナには影響しません。

<a id="upgrade"></a>

### ⬆️ Redmine の版を上げる

`.env` の `REDMINE_VERSION` を書き換えてから、まずビルドだけを実行します。

```bash
docker compose build --pull
```

- ✅ 通ったら、バックアップを取ってから切り替える

```bash
./backup/backup.sh && docker compose up -d
```

- ❌ 落ちたら、エラーから原因のプラグインが分かります。動いている環境はそのままです

> ⚠️ ビルドだけで終える（まだ切り替えない）場合は、すぐに `.env` の `REDMINE_VERSION` を元に戻してください。戻し忘れて `docker compose up -d` を実行すると、その版に切り替わります。

### 🗓️ 毎月やること

公式イメージは同じタグのまま OS のセキュリティ修正が入ります。取り込むには次を実行します（PostgreSQL のイメージは `build --pull` では更新されないので、別に取り直します）。

```bash
docker compose build --pull
docker compose pull db
./backup/backup.sh && docker compose up -d
```

<a id="backup"></a>

### 💾 バックアップ

```bash
./backup/backup.sh
```

- DB（`pg_dump`）、添付ファイル、構成ファイルを `backup/archive/<日時>/` に保存し、7世代を残します
- 保存先と世代数は `BACKUP_DIR` と `KEEP_GENERATIONS` で変えられます
- 毎日の定期実行の例（cron）。✏️ パスは置いた場所に合わせます

```bash
30 2 * * * cd /path/to/docker-redmine && ./backup/backup.sh >> backup/backup.log 2>&1
```

> 🔐 構成ファイルのバックアップには `.env`（パスワード類）が、DB のバックアップには利用者の情報が含まれます。そのため、バックアップは実行したユーザーだけが読める権限で作ります。よそへコピーするときも、権限に注意してください。

### ♻️ リストア

```bash
docker compose down
rm -rf data/postgres && mkdir -p data/postgres
docker compose up -d db
docker compose ps db   # db が healthy になるまで待つ
zcat backup/archive/<日時>/redmine-db.sql.gz | docker compose exec -T db psql -U redmine -d redmine
tar xzf backup/archive/<日時>/files.tar.gz -C ./data
docker compose up -d
```

- `db` が `healthy` になる前に流し込まないこと（初期化が終わっていないため）
- 流し込みの出力に `ERROR` が無いことを確かめます

### ↩️ 前の版に戻す

`.env` の `REDMINE_VERSION` を戻して `docker compose up -d` します。前のイメージが残っているので、再ビルドは要りません。

> 🔴 ただし、新しい版でマイグレーションが走った後は、イメージを戻しても DB は戻りません。版を下げるときは、更新前のバックアップから DB をリストアしてください。

### 📜 ログを見る

ログは標準出力に出ます（`log/production.log` はありません）。

```bash
docker compose logs --tail=200 redmine
```

> 📌 存在しない URL への 404（`/favicon.ico` など）も `FATAL` として記録されます。

## ⚠️ 知っておくこと

- 🏷️ **名前の絵文字**: PDF 出力（チケット一覧・チケット・ガント）では絵文字が化けて、直後の日本語まで崩れます。絵文字ごと出力したいときは Excel 出力を使います。CSV インポートはトラッカー・ステータス・優先度を名前の完全一致で照合するので、CSV を UTF-8 で保存して絵文字ごと書くか、取り込み画面でトラッカーを固定で選びます
- 🧩 **チケットパネル**: 既定のクエリか保存済みクエリから開いて使います。保存していない絞り込みで開くと、ドラッグした直後の件数やカードの位置の表示がずれます（再読み込みで直る）。一度に出るカードは「ガントチャート最大表示件数」（500）までで、500枚だと表示に数秒かかります
- 🧜 **Mermaid**: `redmica_ui_extension` は Mermaid 用の JavaScript（2.6MB）を全ページで読み込みます（2回目からはブラウザのキャッシュが効く）。Redmine 本体が Mermaid に対応した版へ上げるときは、プラグインも新しいタグに上げます
- ✉️ **メールの送信待ち**: Redmine のプロセスの中で管理されます。管理 > 情報 に「キューアダプターが既定のまま」と出ますが、小規模なら問題ありません

## 🚫 やってはいけないこと

- ❌ コンテナの中で `git clone` / `apt-get install` / `bundle install` をする（コンテナを作り直すと消える）。変更はすべて `plugins.tsv` や `Dockerfile` に書いてビルドする
- ❌ Redmine 本体やプラグインのソースを直接書き換える
- ❌ 本番で `data/` を消す（DB と添付ファイルが消える）
- ❌ パスワード・メールアドレス・Webhook の URL などの実際の値をコミットする
